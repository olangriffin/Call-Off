# Design System

## Objective
Call-Off should feel professional, clear, fast and operationally focused.

The interface should prioritise information and action over decoration.

## Principles
1. Clear hierarchy
2. Consistent spacing
3. Consistent component behaviour
4. Minimal visual noise
5. Obvious states and actions
6. Responsive layouts
7. Accessible interaction

## Existing system first
Before creating new UI:
- inspect existing components
- reuse existing styles
- reuse existing patterns
- extend existing components where appropriate

Avoid creating multiple visual patterns for the same interaction.

## Layout
- Maintain consistent page widths and spacing.
- Group related information visually.
- Avoid excessive cards and containers.
- Give important operational information priority.

## Forms
- Keep required fields minimal.
- Use clear labels.
- Provide sensible defaults.
- Show validation close to the affected field.
- Preserve entered data after validation failures where practical.

## Tables
Tables should optimise scanning.

Prioritise:
- name/identifier
- status
- responsible person
- important dates
- risk
- required action

Avoid unnecessary columns.

## Status
Status colours must have consistent meanings throughout the application.

Do not rely on colour alone to communicate important information.

## Interaction
Actions should be:
- visible
- predictable
- reversible where appropriate
- confirmed when destructive

Avoid unnecessary animations or interaction delays.

## Responsive behaviour
Pages should remain usable on smaller screens.

Important actions and information must not disappear purely because the viewport is smaller.

## Accessibility
Maintain:
- keyboard accessibility
- usable focus states
- semantic HTML
- readable contrast
- clear labels
